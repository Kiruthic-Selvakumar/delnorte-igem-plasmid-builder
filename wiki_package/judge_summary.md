# Judge Summary — Automatic Plasmid Design

**Problem.** Existing plasmid-design tools (including our own Template-Guided mode) assume the user already knows which backbone/architecture to use. Teams that only have *a biological part* — their own gene, promoter, or a part borrowed from another team — still have to manually pick a template and hope it fits.

**What we built.** A **constraint-based, part-first, evidence-grounded, multi-objective plasmid design decision engine.** The user supplies a biological part (from our catalog or a completely external/custom part), a host, and a design goal. The engine determines a supported architecture, generates multiple candidate plasmids, applies hard biological/assembly constraints, preserves every user-locked component exactly, analyzes assembly (Gibson primers, restriction-site conflicts), compares candidates against real cached iGEM Registry records, ranks candidates with a weighted multi-objective score, runs a Pareto (trade-off) analysis, evaluates how stable the ranking is, explains its recommendation in plain language, and hands the winning design directly into our existing plasmid workspace (map, parts, sequence, assembly, export).

**Why this differs from Template-Guided.** Template-Guided is manual/expert-controlled: you pick the template. Automatic Design *solves the design problem itself* — it is a decision-support engine, not a form-filling wizard.

**What makes it sophisticated.** Not machine learning — a transparent constraint/search/scoring pipeline: requirement planning → architecture search → constraint validation → assembly analysis → Registry comparison → multi-objective ranking → Pareto analysis → robustness analysis → traceable explanation.

**How we tested it.** 305/305 automated unit/integration tests pass. Across a **catalog-wide sweep of 746 CDS anchors × 8 supported host/goal combinations (5,968 runs)**, the engine produced a hard-valid, assembly-feasible design **99.4% of the time**, with **100% anchor preservation** in every single run. A **leave-one-out test removing 93 real genes from the active catalog and resupplying them as raw pasted DNA** produced materially identical outcomes to the catalog-known path in **100% of 584 comparisons**, with zero exceptions. A **2,000-trial randomized property-stress test found zero invariant violations**. A **role-generalization sweep across all 10 supported biological roles (1,816 runs)** found **100% registration success, 100% anchor preservation, 0% exceptions, and 0% unjustified rejections.**

**Can another team use its own part?** Yes. A part is registered in-session — never written into our parts database — and is immediately usable as the design anchor. Registering the part always succeeds; whether the engine can build a *complete* plasmid from it alone is a separate, honestly-reported question (a custom CDS is usually enough on its own; a custom promoter correctly asks the user which CDS it should regulate, rather than guessing).

**Limitations.** This is a computational design tool: a recommended design *passes our own computational design constraints* — it is **not** experimentally validated, and Registry presence is not wet-lab validation. Compared against Template-Guided on shared templates, both tie on basic buildability where a template already exists (Automatic's value there is no backbone choice required, multiple ranked alternatives, and Registry/robustness analysis); Automatic uniquely builds a working design (bsub_delnorte) where the fixed template alone could not. Robustness measures sensitivity to scoring-weight perturbation, not biological success probability.
